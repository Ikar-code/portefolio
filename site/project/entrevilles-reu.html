Contexte du projet

Projet du BTS SIO (option SLAM), parmi mes réalisations de fin d'année. Le sujet « Intervilles Challenge » demande une application permettant d'organiser et de gérer une compétition où plusieurs équipes de villes différentes enchaînent des épreuves sportives. Les organisateurs gèrent équipes, participants, épreuves et résultats, tandis que les visiteurs consultent scores et classement.

Projet mené en équipe : la conception de la base de données a été réalisée par un coéquipier, et j'ai développé le site (back-end PHP, vues, authentification, déploiement).

04

Architecture MVC

Tout est écrit à la main, sans Composer ni framework, pour comprendre et pouvoir expliquer chaque brique. Voici le chemin d'une requête :

1Front controller : index.php est l'unique point d'entrée, et .htaccess y redirige toutes les requêtes.
2Routeur maison : associe l'URL à un contrôleur et à une méthode, avec gestion des paramètres comme /epreuves/{id}.
3Contrôleurs : un par domaine fonctionnel (accueil, authentification, épreuves, équipes, classement, profil, administration).
4Modèles : une classe par entité (Ville, Sport, Equipe, MembreEquipe, Epreuve, Participation, Utilisateur), qui contiennent toutes les requêtes.
5Vues : un fichier PHP par page, assemblé dans un layout commun avec des partials (navbar, footer).

Le dossier Core regroupe aussi une classe Auth, un client Supabase, un autoloader et un contrôleur de base.

05

Base de données en 7 tables

TableRôle
villeVilles participantes
sportDisciplines proposées dans les épreuves
utilisateurComptes, identifiants et rôles
equipeÉquipes représentant une ville
membre_equipeMembres d'une équipe, avec rôle, pénalités et récompenses
epreuveÉpreuves, planning et statut
participationInscription d'une équipe à une épreuve et son résultat

Deux choix de conception

  • participation fusionne l'inscription d'une équipe à une épreuve et son résultat. Le statut sert à l'inscription, tandis que le score et le classement restent vides tant que l'épreuve n'a pas eu lieu : une table de moins.
  • membre_equipe porte le rôle interne (capitaine ou joueur) ainsi que les pénalités et récompenses individuelles, avec une clé primaire composée qui empêche un doublon dans une équipe.

Le classement par ville n'est pas stocké : il est recalculé à la volée par une vue SQL qui additionne les scores des équipes de chaque ville.

06

Sécurité de l'application

  • Mots de passe hachés avec password_hash() et password_verify(), jamais stockés en clair ni en session.
  • Sessions PHP natives et contrôle d'accès par rôle (exigerConnexion(), exigerAdmin()).
  • Échappement systématique des sorties (htmlspecialchars) contre les failles XSS.
  • Dossiers sensibles protégés par .htaccess (Require all denied).
  • Clés Supabase hors du dépôt Git, dans un fichier ignoré par .gitignore.
  • Mutations passées uniquement en POST.
07

Défis rencontrés

01

Un hébergement qui n'exécute pas le PHP

Hébergement

Problème : sur Vercel, le navigateur téléchargeait les fichiers au lieu de les exécuter, et GitHub Pages n'exécute pas le PHP non plus.

Solution : passage à un hébergeur PHP gratuit, en gardant GitHub pour le code.

02

Pilote PostgreSQL absent

Accès aux données

Problème : l'extension PDO PostgreSQL n'était pas disponible sur l'hébergement gratuit.

Solution : PDO remplacé par des appels à l'API REST de Supabase en cURL, via un client dédié.

03

Fichiers .env refusés

Configuration

Problème : l'hébergeur refuse les fichiers dont le nom commence par un point.

Solution : la configuration se charge désormais depuis un fichier PHP (env.local.php) créé sur le serveur et exclu de Git.

04

Authentification absente du schéma

Sécurité

Problème : la table utilisateur n'avait pas de colonne mot de passe.

Solution : écriture d'une migration SQL séparée, pour ne pas modifier le travail de l'équipe sans validation.

05

Changement de pile en cours de route

Choix techniques

Problème : le projet a démarré en Next.js et React.

Solution : reprise complète en PHP et MVC, pour maîtriser le code et pouvoir le défendre à l'oral.

06

Fonctionnalités manquantes détectées en test

Tests

Problème : pas d'inscription, lien de profil sans route, vue de classement non créée.

Solution : ajout des routes, des contrôleurs et des vues correspondants.
